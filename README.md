# Everything WoW Companion 0.2.6

The Everything WoW Companion records what Blizzard's API does not publish: where an NPC stands, where a quest starts, what a vendor sells, what a kill dropped, and what your own character is wearing. An addon cannot send anything over the network, so the Companion writes what it sees to its saved variables file and you upload that file when you feel like it. Nothing leaves your computer until you choose to upload it.

This is version 0.4.2. It is free and open source under the MIT license.

## Changes

**0.4.2** mends two things the first look at the real map showed.

- **The map came back blank.** After a look at the Recorded page, the Route page's map was gone. The window kept its "show this continent" under the name of the frame's own call that shows it, so the map, once put away, could not be shown again. It has a name of its own now, and a test holds every such name clear of the frame's own.
- **The minimap button was too big.** The mark is drawn at the size the game's own round buttons are; the button around it stays a little larger so it is easy to hit.
- **Zone names.** They are set a little further apart on the map, so fewer lie on one another.

**0.4.1** times the boats, zeppelins and the tram. The site's map guesses how long each line takes; now each ride you take is written down, as each flight already is, so the guesses can be replaced by what the ride really took.

- **`Rides.lua`.** One ride is one observation of the new kind `transit`: where it began, the seconds from setting off to coming to rest to a tenth, your faction, where it ended, and how many loading screens it passed through. Nothing else of the player is in it.
- **How a ride is told.** On a boat your character stands still and yet moves over the ground fast. Twice a second the addon compares how far the character has moved in the world with how fast it is moving on its own feet; a good deal faster than its own speed, for a few looks running, is a ride, and it ends when that stops for a few seconds. A boat that calls at a dock on its way is one ride for each leg.
- **What is left out.** A flight, which the flight recorder times; anything inside an instance; a ride under half a minute or over a quarter of an hour; and one that ends where it began with no loading screen between.
- **WoW Forever alone.** The recorder starts only there, where the planner's lines are, and only where the client gives the character's position, its speed and a ticker. A look the client will not answer is passed over.
- **The site.** everythingwow.com takes the kind in from its build of 25 November 2026, and its upload page counts it as Transport Rides; the window's Recorded page uses the same words.
- **The version and the tests.** Both tables of contents list `Rides.lua` and carry `## Version: 0.4.1`. The tests ride a plain crossing, one through a loading screen, one that ends with it, and each kind that must not be written, then stand in for the client and look at it as the ticker does; the site's own reader accepts a file holding a ride. The suite reads 2,983 assertions, from 2,931, under Lua 5.1 and 5.4.

**0.2.13** leaves alone the items the site already has. On 24 November 2026 the owner's first file from 0.2.12 held 400 item observations, the session's whole allowance, and 340 of them were items the site already had from Blizzard: an id of 200,000 or more turned out to be a weak sign of a missing item, since Blizzard's own WoW Forever data holds 11,770 such ids.

- **`Known.lua`.** A new file holds those 11,770 ids as 2,147 ranges, as the site's public database held them on 24 November 2026. It is data, not code, and nothing in it is read from the player's game.
- **The recorder.** `Items.lua` no longer notes an item on that list, and never asks the item cache about one. Everything else is as in 0.2.12: WoW Forever alone, ids from 200,000 up, once per item per fourteen days, 400 a session.
- **A stale list is harmless.** A listed item is one the site has. An item Blizzard adds later is noted and the site leaves it alone, since it adds a page only where it holds none. A list that cannot be read is treated as no list, and every item is noted as before.
- **The version and the tests.** Both tables of contents list `Known.lua` and carry `## Version: 0.2.13`. The tests read the shipped list (its order, its 2,147 ranges and 11,770 ids), a listed and an unlisted item, the ends of a range, a single id, the gaps, and five lists that cannot be read; the suite reads 842 assertions, from 806, under Lua 5.1 and 5.4.

**0.2.12** notes the items Blizzard's item API does not hold. On 23 November 2026 the site's worker asked the API by id for four items WoW Forever's own auction houses sell, and each answered 404; 295 of the 296 auction items the site had no page for were new WoW Forever items, ids above 200,000. Their names and what they are can only come from players.

- **A new kind, `item`.** The first time the addon meets such an item, at the auction house, in loot, at a vendor or in a quest's rewards, it writes one observation of it from the client's own item cache: `n`, the name; `ql`, the quality number; `il`, the item level; `rl`, the level it requires; `c` and `sc`, the class and subclass numbers; `slot`, the equip location token; `stack`; `sell`, what a vendor pays in copper; `bind`; `stats`, the base item's stats by the client's own keys; and `sp`, the spell a use triggers.
- **The same for every player.** The item is asked for by its bare id, never by the link in front of the player, so a random suffix, an enchant or a maker's name never reaches the file. Nothing of the player is in the observation and no position is written.
- **WoW Forever alone, and once.** It runs only on WoW Forever and only for ids from 200,000 up, where the gap is. The saved file remembers the day each item was noted (`items`, beside `observations`) and notes it again only after fourteen days, after a patch or after `/ewow clear`. A session writes at most 400, so a first walk through a full auction house never pushes the NPCs, loot and quests out of the buffer.
- **No new event and no query.** The recorders that already meet items hand them over. An item the client has not loaded yet is tried again the next few times an item is met, the way the deals window reads a sell price, and then left for another session.
- **Before the site reads it.** The site's reader drops a kind it does not know and counts it, and reads the rest of the file as before, so this version is safe to run ahead of the site.
- **The version and the tests.** Both tables of contents list `Items.lua` and carry `## Version: 0.2.12`. The tests note an item from each of the four places, a stacking item with a use, a name holding a client code, an item the client has not loaded, the session cap, the fortnight, a patch and a clear, and prove every other client writes nothing; the Forever file they write carries an item observation and the saved memory, which the site's own parser reads. The suite reads 806 assertions, from 726, under Lua 5.1 and 5.4.

**0.2.11** records what the quest window says. On 23 November 2026 the owner asked for a quest's text, objectives and rewards: Blizzard's WoW Forever quest index holds a small part of the game's quests, and the pages the site makes from this addon's quest titles carried a name and a quest giver and nothing else.

- **At the offer.** A `quest_start` observation now carries `text`, the quest's description, and `objectives`, what the player is asked to do.
- **At the turn in.** A `quest_end` observation carries `completion`, what the NPC says.
- **At both, where the window shows them.** `rewards` and `choices`, each a list of `{ id, q, n }`, `n` being the item's name as the window shows it, so the site can name a reward Blizzard's item index does not hold; `money` in copper; `xp`; and `level`, the quest's level, where the client can give it.
- **The player is never recorded.** The game writes the character's own name into quest text, so every text is scrubbed before it is stored: the name, whole and word by word, becomes the token `<name>`. The client's color codes are removed, and a text still holding a link or a control character other than a line break is not recorded at all. Class and race words are left as the game wrote them.
- **Sizes.** The description is kept to 1,600 bytes, the objectives to 600 and the completion text to 1,200, each cut on a character boundary, and the whole payload is then held under the reader's 4,000 byte cap by shortening the longest text first and marking it `cut`, so a long quest is recorded shorter rather than dropped.
- **No new event and no new call outside the quest window.** The two events are the ones the recorder has used since its first release. Every function is one the quest window itself is drawn from, each inside `pcall`, and a client without one records the quest as before.
- **The version and the tests.** Both tables of contents carry `## Version: 0.2.11`. The tests read an offer and a turn in with rewards and choices, a two word name, a link, a control character, a cut inside a character and a quest whose text swells in JSON, and the Forever file they write now carries a quest's text, which the site's own parser reads; the suite reads 726 assertions, from 678, under Lua 5.1 and 5.4. The site does not show these fields yet.

**0.2.10** reads a grouped item row as the price of one. On 23 November 2026 the owner opened Blue Leather Bag from the new window and the row changed to "Buy 64 for 62s 32c": the auction house showed 15 bags at 8 silver 67 each, and the addon had taken 8 silver 67 for all 15.

- **The cause.** The modern auction house groups identical auctions of an item into one row, and `GetItemSearchResultInfo` gives that row's `buyoutAmount` as the price of one and `quantity` as how many there are at that price. Both readers took `buyoutAmount` for the whole row.
- **The window.** An item search now counts a row as `quantity` at `buyoutAmount` each, so the bags read as what they are: a few copper under the vendor's price each, and only the rows priced under it.
- **The recorder.** The same read in `Auction.lua` wrote such a row with `unit` as the price divided by the quantity. It now writes `unit` as the price of one and `buyout` as the price of the row, as the browse and commodity reads always have. Rows of one, which is most gear, were always right. The site publishes no price from these rows (its Forever prices come from Blizzard's auction data through the worker), so nothing shown on the site was wrong.
- **`/ewow deals min <amount>`.** Hides deals with less profit than the amount, for the session: `/ewow deals min 50s`, `/ewow deals min 1g`, and `/ewow deals min 0` to show every deal again.
- **The version and the tests.** Both tables of contents carry `## Version: 0.2.10`. The tests read the owner's own row of bags through both readers and fail against 0.2.9; the suite reads 678 assertions, from 656, under Lua 5.1 and 5.4.

**0.2.9** adds a window of auctions listed under their vendor price. On 23 November 2026 the owner asked for the addon to look for items being sold for less than a vendor pays for them, and to show what to buy and for how much, from the same auction house reading the recorder already does.

- **What it finds.** An auction is a deal when its buyout for one item is lower than the item's vendor sell price, so buying it and selling it to any vendor leaves a profit. An item no vendor buys is never a deal, and neither is one of the player's own auctions. The sell price is the client's own, from its item cache; an item the client has not loaded yet is asked again a second later, up to three times.
- **How it reads.** Exactly as the recorder does: only the results the player's own search has already loaded, on the same events and through the same getters, never in combat. It sends no query, buys nothing and bids on nothing. A commodity search or an item search gives every listing, so its row is exact: how many to buy, what they cost, what a vendor pays and the profit. The browse list gives only each item's lowest price, so its row is the price of one, marked `1+`, until the player opens the item. On a client without `C_AuctionHouse` it reads each page of the classic list. It runs where the recorder reads the auction house, which is Forever and the classic clients, and is idle on Retail and on a client the addon cannot place.
- **The window.** It opens by itself beside the auction house the first time a visit finds a deal, lists the deals with the most profit first, twelve to a page, and closes with the auction house or with Escape. A row shows the item's tooltip under the pointer, and a click hands the item's link to the client the way a shift click does. Every call that builds it sits inside `pcall`, and on a client where it cannot be built the list is printed in chat instead. A new visit to the auction house starts a new list.
- **`/ewow deals`.** Opens or closes the window. `/ewow deals list` prints the list in chat, `/ewow deals clear` empties it, and `/ewow deals auto off` keeps the window closed until asked for, for the session, with one line of chat when a deal is found.
- **Nothing is uploaded.** A deal is never written to the saved file: `EverythingWoWDB` is unchanged, and so is everything the site reads.
- **The version and the tests.** Both tables of contents list `Deals.lua` and carry `## Version: 0.2.9`. The tests drive the finder through a stand in `C_AuctionHouse` and a stand in item cache on Forever, Retail and Classic Era, prove no query is ever sent and nothing reaches the saved file, and build the window against a stand in frame; the suite reads 656 assertions, from 573, under Lua 5.1 and 5.4. The window itself has not been seen in a game client.

**0.2.8** records what kind of creature an NPC is and the title under its name. On 12 November 2026 the owner asked that the site's pages for NPCs the Companion has named say more than a name: the level and whether a creature is elite or rare were already in every sighting, and the type and the title were not.

- **The creature type.** A sighting now carries `creature_type`, the client's own word for the kind of creature, "Beast" or "Humanoid", read from the unit itself wherever a sighting is made. A client that names none writes none.
- **The title.** A sighting carries `title`, the line a creature shows under its name, "Innkeeper" or "Flight Master". No unit function returns it, so it is read from the second line of the creature's own tooltip, and only while the tooltip is on that creature: a nameplate sighting made while the pointer is elsewhere carries no title. The level line, which sits second on a creature with no title, is told apart by the client's own word for level. A line with a color code or a control character, or longer than 64 characters, is not recorded. A player, a pet and a vehicle are passed over before either read, as they always were.
- **The version and the tests.** Both tables of contents carry `## Version: 0.2.8`. The tests read a titled innkeeper, a boar whose second line is its level line, a nameplate sighting under another unit's tooltip, a painted line, an over long line and no tooltip; the suite reads 573 assertions, from 563, under Lua 5.1 and 5.4.

**0.2.7** keeps the saved file small enough to upload. On 8 November 2026 the owner's file passed 8 MB, the most the site's upload page reads, and the page refused it. The buffer was held to 5,000 observations but not to a size, and Forever's auction pages, which 0.2.6 began reading from the player's own searches, run to about 1.5 KB of JSON each, about 2.6 KB in the saved file: in the owner's 6 November file 727 auction pages took 1.9 MB of its 2.9 MB, and a buffer that fills with them passes 8 MB well before 5,000.

- **Two byte budgets beside the 5,000.** The buffer is now also held to 3,600,000 bytes of JSON, measured the way the upload page measures what it sends, which is about 6 MB on disk and sits under the 3,900,000 byte body the page sends in one upload, so every observation in the file goes up together. Inside that, auction pages have a budget of their own, 1,200,000 bytes, about 800 pages, and past it the oldest auction page is dropped rather than the oldest observation, so a long session at the auction house never pushes out NPCs, loot, quests, or vendors. Every observation either budget lets go is counted in `dropped`, as the 5,000 always has been, and the newest observation is never dropped.
- **A file already over budget shrinks.** The budgets are applied once when the addon loads as well as after every write, so a file 0.2.6 wrote past 8 MB is cut back at the next login, oldest auction pages first, and the game writes the smaller file at the next logout or `/reload`.
- **The version and the tests.** Both tables of contents carry `## Version: 0.2.7`. The tests fill the buffer with auction pages past their budget beside 50 NPCs and prove every NPC is kept, fill it with vendors past the file budget, prove the running totals match a fresh measure, and load a 4,000 page file written before 0.2.7 and prove it is pruned to both budgets; the suite reads 563 assertions, from 548, under Lua 5.1 and 5.4. A 6,000 observation Forever session, a third of it auction pages, writes a 2.9 MB file that the site's own parser reads whole.

**0.2.6** records each class's talent trees for the site's talent calculators. On 20 October 2026 the owner decided the Classic three tree calculator's data is recorded by the Companion from the game client's own talent functions: Forever first, on its launch day, 4 November 2026, with a fresh character of each of the nine classes, and Classic Era later. Blizzard's Classic Game Data API publishes no talent document, and a datamined table or another site's database is not a source the site uses, so the client is the only source.

It also makes the addon silent at login and reads Forever's auction house. On 24 October 2026 the owner asked that the chat line 0.2.2 printed in Forever, "Auction recording is off for this client; the auction listener stays idle.", go away, and that the addon upload as much data as it can.

- **Silent idle recorders.** No recorder prints anything at login any more. The idle auction line 0.2.2 added was the only one; it is gone, and `/ewow status` now names the recorders that cannot run on the client instead, on an `idle on this client:` line, for example "kill counter (combatLog off)" on Forever or "auction recording (the site reads Blizzard's auction API)" on Retail. Every command's own output, `/ewow status`, `/ewow probe`, `/ewow talents` and the rest, is unchanged, and so is the line a forbidden action report prints.
- **Forever's auction house, read from your own searches.** Forever's client carries the Retail project id, so its auction house is the modern `C_AuctionHouse` one, which the classic `AUCTION_ITEM_LIST_UPDATE` scan cannot read, and Blizzard publishes no auction API for Forever's realms. A new reader in Auction.lua reads what your own searches have already loaded: the browse list (`AUCTION_HOUSE_BROWSE_RESULTS_UPDATED` and `_ADDED`, through `C_AuctionHouse.GetBrowseResults`: each row's item, lowest price and total quantity), a commodity search (`COMMODITY_SEARCH_RESULTS_UPDATED` and `_ADDED`: each listing's unit price and quantity) and an item search (`ITEM_SEARCH_RESULTS_UPDATED` and `_ADDED`: each auction's buyout and quantity). ## Installing

1. Close World of Warcraft.
2. Copy the `EverythingWoW` folder from a release package into your addons folder, or clone this repository into a folder of that name there:
   - Windows: `C:\Program Files (x86)\World of Warcraft\_retail_\Interface\AddOns\EverythingWoW`
   - macOS: `/Applications/World of Warcraft/_retail_/Interface/AddOns/EverythingWoW`
   - On Classic Era, replace `_retail_` with `_classic_era_`.
3. Start the game, open the character select screen, click AddOns, and make sure Everything WoW Companion is checked.
4. Play. Type `/ewow` at any time, or click the Companion's button on the minimap, to open its window and see what has been recorded.

The folder must be named `EverythingWoW`, because the game looks for a table of contents file with the same name as its folder.

## Which game versions this supports

## Recording the Talent Trees

The site's Classic and Forever talent calculators are built from each class's trees as the game client itself shows them, and the Companion records them on `/ewow talents`.

On launch day, log in a new character of each class, type `/ewow talents`, then `/reload`. Then send your SavedVariables file to the Orchestrator. A level one character is enough where the client shows the trees from level one; if the addon says no trees could be read and suggests level 10, read that class again once it reaches level 10.

The file is the same one you upload:

```
World of Warcraft/_<flavor>_/WTF/Account/<ACCOUNT>/SavedVariables/EverythingWoW.lua
```

where `_<flavor>_` is the game's own folder, such as `_retail_` or `_classic_era_` (Forever's is whichever folder its launcher installs into). The trees are kept in their own part of that file, `EverythingWoWTalentsDB`, which the upload page does not read yet, so uploading the file on the site as usual still works and sends only the observations. Each class is held once per game version and a second read of the same class replaces the first, so nine runs give nine entries. `/ewow clear` leaves them alone and `/ewow talents clear` throws them away. Only the class and the level of the character are recorded beside the trees: no name, no realm, and no talent you have spent.

## What is recorded

| What | When |
|---|---|
| NPC sightings | A nameplate appears, you mouse over a creature, or you target one. The creature id, name, level, reaction, map, and position. |
| Rare sightings | The same moments, where the creature is rare, rare elite, or a world boss. |
| Game objects and gathering nodes | When you loot the object, which is the one moment its id can be read exactly. On Retail, also when the tooltip for the object under your cursor carries an id. |
| Quests | When a quest is offered and when it is turned in: the quest id, the map and position, and the npc who gave or took it. |
| Vendors | When a merchant window opens: the vendor npc and up to 100 of its items, each with its price in copper, its stack size, and, where it is bought with something other than money, the currency id and how much of it the item costs. |
| Loot and kills | When a loot window opens: the source and the items, gold included. A kill your group made that nothing dropped from is recorded as an empty loot event, because a drop rate needs the kills that dropped nothing as much as the ones that did. |
| Your character | Once on login, after the client has loaded your gear and currencies, and on `/ewow snapshot`: your gear per slot, talents, professions, reputations, and currencies. After that, only when an hour has passed and your gear or your level has changed. |
| Your class's talent trees | Only on `/ewow talents`: every tree and talent of your class, with each talent's place, maximum rank and prerequisite, kept apart from the observations. |
| Auction rows | From a search you ran yourself, never from a scan of the addon's own: the addon never sends a query to Blizzard. On a client with the classic auction list, such as Classic Era and Hardcore, each row's item, quantity, and price. On Forever, and on a classic client whose auction house is `C_AuctionHouse`, from 0.2.6: each browse row's item, lowest price and total quantity, each commodity listing's unit price and quantity, and each item auction's buyout and quantity. Retail is skipped entirely, because Blizzard's own auction API is what the site reads there. |
| Boat, zeppelin and tram rides | On WoW Forever, when a ride you took comes to rest: where it began and ended, how many seconds it took, your faction, and how many loading screens it passed through. |
| Flights | When a flight you took lands: the two flight points, how many seconds it took, the faction whose network it is, and where you took off and landed. Only a flight seen from end to end. |
| New WoW Forever items | On WoW Forever only, the first time you meet an item with an id of 200,000 or more that the site does not already have from Blizzard, at the auction house, in loot, at a vendor or in a quest's rewards: the item's name, quality, levels, kind, slot, stack size, vendor price, binding, base stats and use spell, as the client's item cache gives them for the bare item. Once per item per fourteen days, at most 400 in a session, and with no map or position. |

## What is never recorded

- No chat, of any channel, ever. Not say, not whisper, not guild, not party.
- No other player's name, level, guild, or gear. Other players' identifiers are used in memory to tell whether your group killed something and are never written to the file.
- No account data: no email address, no Battle.net tag, no payment information, no password. The addon cannot read them and does not look.
- No combat log. Combat logs come from the game's own `WoWCombatLog.txt` and have nothing to do with this addon.
- No auction seller names, although the client hands them to the addon. They are read past and thrown away.

The only character named in the file is your own. The snapshot carries your character's name and realm because it exists to fill in your own character page on the site, and that is the only place in the file a character name of any kind appears. The addon reads a name from a unit in one other place, the creature on a nameplate, a mouseover, or your target, and it stops before reading it if the unit is a player, a pet, a guardian, or a vehicle, so a person's name can never reach the file through it.

The map id and the coordinates are the client's own: `C_Map.GetBestMapForUnit("player")` gives the uiMapID of the map you are standing on and `C_Map.GetPlayerMapPosition` gives your place on it as two fractions from 0 to 1 with the origin at the top left. That uiMapID is the identifier the site's zone maps and pins are keyed by, so nothing is converted anywhere.

## Slash commands

| Command | What it does |
|---|---|
| `/ewow` | Opens the Companion's window: the Route page with its map, the Recorded page and a button for the Deals list. `/ewow show` and `/ewow window` do the same. Where the client cannot build the window, it prints the status instead. |
| `/ewow minimap` | Hides the Companion's button on the minimap, or shows it again. |
| `/ewow status` | The client detected, the capability table, the recorders that cannot run on this client, the last forbidden action reported, the counts per kind, the number dropped, and the skipped, deduped, and ignored counts with the reason for each, plus the game version and the patch. |
| `/ewow route <place>` | On WoW Forever, plans the trip to a place from where you stand, with the site's own planner: the steps and the time. `/ewow route` alone opens the window's Route page. `/ewow route <place> > <place>` plans between two places, and `/ewow route speed foot`, `travel`, `60` or `100` sets the speed routes are timed at. Records nothing. |
| `/ewow clear` | Throws away everything recorded so far. Start here if you would rather not upload something. |
| `/ewow snapshot` | Records your character snapshot now rather than waiting for the next login. |
| `/ewow path` | Prints where the file is written. |
| `/ewow probe` | Attempts every event this addon registers, one at a time, and prints whether the client allowed or refused each one. Saved to the file under `db.probe` as well. |
| `/ewow talents` | Records your class's talent trees as the client shows them, and prints how many trees and talents it read. See Recording the Talent Trees. `/ewow talents clear` throws every recorded tree away. |
| `/ewow cap <name> on\|off` | Flips one capability, `worldCursor`, `unitGuid`, `combatLog`, `auction`, or `auctionModern`, on or off for the rest of the session, so a capability the probe found safe can be tested on its own. Does not persist past a reload. |

## Limits of this version

The addon is honest about what it cannot see, because a guessed id would become a map pin on the site.

- A game object the client shows only as a tooltip has no documented id on Classic Era, and `GameTooltip:GetOwner()` names the frame rather than the thing in the world. Where no id can be read, nothing is written and the tooltip is counted under `ignored` in `/ewow status`. Only a subject that has an id the client will not place counts as `skipped`, because only that is a loss.
- Vendor and quest giver flags on an NPC sighting are not recorded. Nothing on a nameplate says whether a creature sells or gives quests, so those facts come from the vendor and quest records instead.
- Quest objective locations, trainer lists, and flight paths are part of the file contract and are not recorded in 0.1.0.
- The buffer holds 5,000 observations and, since 0.2.7, at most 3,600,000 bytes of them as JSON, about 6 MB on disk, of which auction pages may take 1,200,000. Past any of the three the oldest are dropped and counted, auction pages before anything else when they are over their own budget. 5,000 is the same number the upload page sends in one file, so upload and then `/ewow clear` if you play a great deal between uploads.

## Developing and testing

The recorders are plain Lua with no libraries. `tests/run.lua` loads the real addon files against a small stand in for the client, fires the events, asserts the saved shape, and writes a file the way the game writes one. The Everything WoW worker's `addon/tests/check-file.mjs`, which stays with the site's code because it reads the site's parser out of the application repository, then reads that file with the site's own parser and with the worker's aggregation readers, so the file is proved against both ends rather than against a description of them. Since 0.2.0, `tests/run.lua` also loads the addon fresh against simulated clients, Retail, Classic Era, Forever, and one the capability table does not recognize, joined in 0.2.4 by Burning Crusade Classic 2.5.6 and Mists Classic 5.5.4 and in 0.2.5 by Wrath of the Lich King Classic 3.80.2, Cataclysm Classic 4.4.2, and a 6.x session the site holds no row for, and asserts the client key, the saved version key, and each restricted capability for its client; since 0.2.2, Forever's own profile has `worldCursor` and `unitGuid` on, so firing one of those gated events there is asserted to write an observation rather than nothing, while `combatLog` and `auction` stay off and their events are asserted to write nothing and raise no error. Since 0.2.1, `stub.state.forbiddenEvents` makes the stand in client refuse one named event's registration the way the owner's own Forever session refused `RegisterEvent()`, which the tests use to prove that a Forever session carrying the mainline project id still reads as `forever`, that the refusal is attributed to the exact event rather than to every capability, and that `/ewow probe` prints and saves one line per event. Since 0.2.2, `stub.state.forbiddenUnregisterEvents` and `stub.state.unregisterAttempts` reproduce the owner's own second alert, naming `EverythingWoWFrame:UnregisterEvent()`, and the tests use them to prove a refused registration is never followed by an unregister call at all and that a refused unregister is still attributed to its own event rather than falling back to every capability off.

Since 0.2.6, `stub.InstallClassicTalents` and `stub.InstallTraits` give the stand in client either talent API for one test at a time, and `stub.RemoveTalentApis` takes them away again, so every other test still reads a client with neither. `stub.InstallModernAuction` and `stub.RemoveModernAuction` do the same for `C_AuctionHouse`, whose commodity and item answers carry a seller and a bidder so the tests can prove neither reaches the file, and `stub.state.invalidEvents` makes `C_EventUtils.IsEventValid` deny an event the way a client without it would.

```
lua5.4 tests/run.lua /tmp/EverythingWoW.lua
```

`lua5.1` runs the same suite.

The run writes five more files beside the first, from a Forever, a Burning Crusade Classic, a Mists Classic, a Wrath of the Lich King Classic, and a Cataclysm Classic session, `/tmp/EverythingWoW-forever.lua`, `/tmp/EverythingWoW-tbc.lua`, `/tmp/EverythingWoW-mists.lua`, `/tmp/EverythingWoW-wrath.lua`, and `/tmp/EverythingWoW-cata.lua`, and the worker's `node addon/tests/check-file.mjs <file>` reads any one of them.

The worker also keeps `addon/tests/fixtures/live-0.1.0.lua`, a file a live Retail client wrote with 0.1.0, with the character renamed and everything else left as it stood. It is the evidence for the three fixes above, so no later version may quietly write a file that looks like it again. Running `node addon/tests/check-file.mjs addon/tests/fixtures/live-0.1.0.lua` in the worker shows what the site made of it: all 28 observations accepted, none refused, and the vendor row the only thing missing a price.
